3. 기능과 시험

기획서의 기능 16가지와 시험 584개입니다.

기능내용
부품 정보 올리기엑셀 한 장에 부품 한 줄. 열 이름이 조금 달라도 읽고, 모르는 열은 알립니다. 한 건 직접 입력도 됩니다.
누락 점검필수 9칸과 HS 후보 자리수를 점검합니다. 목록에 누락 건수를 표시하고 초안에 「[확인 필요]」를 남깁니다.
규칙 초안입력값을 문장 틀에 끼워 네 칸을 씁니다. 받침에 맞춰 조사를 고르고, 없는 값은 지어내지 않습니다.
문체 맞추기 · 칸 이름과거 사례의 끝맺음(…입니다 / …이다 / …임·함)을 따릅니다. 양식 제목과 네 칸 이름을 바꿉니다.
AI 다듬기(선택)보안 확인 후 전송합니다. 세율 수치는 지우고 단정 표현은 짚으며, 반영 단추를 눌러야 초안에 들어갑니다.
내보내기엑셀(물품설명서·입력·안내)과 인쇄용 표 양식을 만듭니다. 작성 구분(규칙·직접 수정·AI)을 함께 남깁니다.
(v1.1) 엑셀 올리기·열 짝짓기여러 파일을 한꺼번에 올리면 종류를 알아보고 머리글 줄을 찾습니다. 못 찾은 필수 열은 사용자가 고르고, 고른 짝은 기억합니다.
(v1.1) 수출입 실적·FTAKPI 카드(합계·계산 구분), 월별 그래프, 본부·국가·업체·HS 4단위 상위 표. 수출은 전년 동기 대비.
(v1.1) 관세환급·오류점수본부 × 월 환급 표, 오류 비율 월별 선, 구분별 표. 0 으로 나누면 「—」.
(v1.1) 거르기·엑셀기간·본부·국가 조건, 금액 단위 표기. 탭별 집계 시트와 계산식 안내를 엑셀로 내보냅니다.
(v1.1) 자료 목록통관 서식·매뉴얼의 이름·분류·사내 위치를 등록하고 찾습니다. 경로 복사, 엑셀로 옮기기.
(v1.2) 양식 6절 초안1절 품명 머리글, 2~6절 다섯 칸. 제출서류 목록 칸은 붙임 자료와 공급자 HS 를 나열하고 없으면 안내만 남깁니다.
(v1.2) 품목분류 결정문 탭결정 건수·0% 결정 비율·절감 추정 카드, 월별 시행 건수 그래프, 완제품·관세사·HS 4단위별 표, 세율별 분포, 결정문 목록. 관세율 「FCN0」 같은 협정 부호도 읽습니다.
(v1.2) 화물 추적 — 단계 가져오기ERP 진행현황 엑셀(열 짝짓기), 유니패스 XML 붙여 넣기, OpenAPI 조회(인증키를 넣고 눌렀을 때만). 같은 BL·단계·처리일시는 두 번 넣지 않습니다.
(v1.2) 화물 추적 — 알림 초안입항보고 제출·수입신고(바꿀 수 있음)가 새로 생긴 건마다 관세사·요청자 앞 메일 초안. 메일 앱으로 열기·복사·카톡용 한 줄, 통보함 표시, 메일 틀 편집, 시간 외 표시.
(v1.3) 오류점수 분석신고번호 앞 5자리로 인천·울산을 나누고, 월별 건수·점수·비율, 분기 경계, 담당자 표 대조, 항목별 원인, 관리대장, 공유 메일 초안.

6. 한계와 남은 일

  • HS 코드를 확정하지 않습니다 — 「후보 · 검토 필요」로만 적고 최종 판단은 담당자가 합니다.
  • 관세율 수치는 싣지 않습니다.
  • 관세청 공식 서식을 재현하지 않습니다 — 첨부 양식에 맞춰 칸 이름을 바꾸는 방식입니다.
  • 실제 AI 호출은 아직 확인하지 않았습니다(요청 모양만 테스트로 고정).
  • (v1.1) 「실시간」은 매일 엑셀을 다시 올리는 방식입니다. ERP·관세청과 자동으로 잇지 않습니다.
  • (v1.1) 예제 열 이름은 지어낸 것입니다. 실제 ERP 엑셀의 열 이름을 받아 같은 뜻 낱말 표를 늘려야 합니다.
  • (v1.1) 금액 단위·통화를 바꾸지 않습니다. 파일마다 단위가 다르면 합계가 섞입니다.
  • (v1.2) 메일을 자동으로 보내지 않고 유니패스를 자동 감시하지 않습니다. 사람이 엑셀을 올리거나 「조회」를 누를 때 읽습니다. 정해진 시각마다 조회하는 일은 사내 서버(배치) 몫입니다.
  • (v1.2) OpenAPI 직접 조회는 브라우저가 막을 수 있습니다(CORS). 막히면 조회 주소를 새 탭에 열어 XML 을 붙여 넣는 방식입니다. 실제 관세청 응답 태그 이름은 연계가이드로 대조하지 못했습니다 — 태그 표(TAGS)를 늘리면 됩니다.
  • (v1.2) 공휴일은 「시간 외」로 판정하지 않습니다.
  • (v1.2) 「02_AI 물품설명서 프롬프트 검토 양식」 엑셀은 DRM 으로 열리지 않아 반영하지 못했습니다(해제본 요청).
  • (v1.3) 유니패스에 접속하지 않는다(받은 엑셀을 올린다). 대시보드 「오류점수」 탭의 비율은 v1.1 정의(오류건수 ÷ 신고건수) 그대로이고, 오류점수 화면의 비율은 기획자 실제 표 정의(오류점수 ÷ 신고건수)다. 첨부 「인천_울산캠퍼스구분자」 파일은 시트가 비어 있어 읽을 내용이 없었다.
  • 업무 자료는 지금처럼 브라우저 안에서만 처리합니다. 로그인 DB 에는 「누가 쓸 수 있는가」와 게시판 글만 있습니다.
  • 로그인 뒤 화면(게시판 · 관리 · 첫 화면 고르기)은 실제 계정으로 눌러 보지 않았습니다. 가입 → 사용 신청 → 승인 → 게시판 글쓰기 확인은 기획자와 관리자 몫입니다.
  • 독립 운영까지 남은 것: 본인 Supabase 프로젝트에 auth.sql · board.sql · site.sql 실행 → js/auth-config.js 의 url · anonKey 교체 → 다시 배포(supabase/README.md)
